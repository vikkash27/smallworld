# Small World

Track C bootstrap baseline: Next.js App Router, TypeScript (strict), Tailwind CSS,
and a local Convex deployment. The landing page is a placeholder owned by Track A.

## Prerequisites

Node.js 22.12 or newer within v22, npm, and internet access for the first Convex
backend download. Keep the local Convex process running while using the database.

## Setup

```bash
npm install
cp .env.example .env.local
npx convex dev --local
```

Complete the CLI's local deployment setup. It may offer anonymous development or
account/project selection. The CLI writes local deployment configuration to
`.env.local`; retain its generated settings. Copy the local admin/deployment key
to the server-only `CONVEX_DEPLOY_KEY` if needed for the future platform client.
Local environment files and database state are ignored by Git.

In another terminal:

```bash
npm run seed
npm run dev
```

Open <http://localhost:3000>. Seeding inserts the 12 directory communities from
`src/shared/fixtures/communities.sample.json` as `listed`. Rerunning skips existing
rows and preserves participation status. Members and other feature data come in
the implementation run. Fixtures describe fictional members and memberships;
see `src/shared/fixtures/FIXTURES.md`.

## Commands

```bash
npm run build
npx tsc --noEmit
npm test
npm run start
npm run convex:dev
npm run convex:deploy
```

`npm test` runs Vitest once and allows the baseline's empty test directories.
Add feature tests in the owning track's directory. `start` serves a completed
production build. `convex:deploy` deploys to the configured Convex target; the
baseline uses `convex:dev` locally. Convex is pinned to 1.31.7 to support the
required `--local` command. Generated Convex bindings are committed and
regenerated by `convex dev` when the schema/functions change.

## Architecture and ownership

The implementation architecture is Next.js API routes → server-side
`ConvexHttpClient` → local Convex deployment. Private access checks and the client
arrive in the implementation run. The browser will access private data through
the Next.js handlers. Provider and deployment keys stay server-side.

The application path alias is `@/*` → `src/*`. `src/shared/contracts.ts` and the supplied fixture
files are copied verbatim from the frozen handoff.

| Track | Reserved paths                                                                                                                              |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| A     | `src/app/(product)/` discovery/community pages, `src/components/{shell,discovery,communities}/`, `src/ui/discovery/`, `tests/discovery-ui/` |
| B     | `src/app/api/intelligence/`, `src/server/intelligence/`, `tests/intelligence/`                                                              |
| C     | `src/app/api/platform/`, `src/server/platform/`, `convex/`, `tests/platform/`, root tooling                                                 |
| D     | `src/app/(product)/{circles,invite,contribute}/`, `src/components/circles/`, `src/ui/circles/`, `tests/circle-ui/`                          |

`src/ui-kit/` is reserved for shared primitives. A takes ownership of the root
layout and global styles after bootstrap. A must remove `src/app/page.tsx` when
adding `src/app/(product)/page.tsx` so the `/` route has one owner.

The schema covers all 11 domain tables with contract string IDs, ISO date strings,
explicit nullable values, and workspace/data mode fields on private records.
Convex indexes support membership, circle/member, invitation recipient, and token
hash uniqueness lookups. Indexes alone do not enforce uniqueness: future write
mutations must check them inside the same transaction. `seed:run` is internal and
can be invoked by the CLI; no public feature functions or API handlers exist yet.
